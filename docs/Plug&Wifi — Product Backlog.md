## **Global Platform Assumptions & Core UI (v4)** 

* **Landing Page & Frictionless Onboarding:** The initial role selection screen is completely removed. The default landing experience assumes the visitor is a standard space user (consumer). A clear option to "Register as a Space Provider" is located in the top-right corner of the navigation bar.  
* **"Register Later" Flow:** Users can browse as unregistered guests. If an unauthenticated guest attempts to book a workspace, an in-context login/registration pop-up modal triggers instead of a full-page redirect to preserve purchase intent.  
* **Layout Adaptability Rules:** The Web/Desktop App defaults to a Grid View ("Available Near You") showcasing 6 geo-localised venues with a "More Venues" expansion trigger. The Mobile layout defaults to a Map View with a draggable/swipe-up bottom sheet containing venue cards.  
* **Map Interface Design:** Map pins utilise uniform colored dots mapped to venue categories (Blue \= Cafe, Red \= Restaurant, Green \= Hotel, Grey \= Other). Pins dynamically collapse into numbered clusters when zooming out.  
* **Core UI Telemetry:** Venue cards show: Name, rating, short description/category, availability window, hourly fee, distance, WiFi score, power outlet availability, noise level, and a prominent Book a Space CTA button.  
* Filtering Taxonomy: Search and map interfaces feature toggle filters for: No Loud Music, Calls Allowed, 4+ Stars, Accessibility Friendly, and diversity filters following Diverse-owned business classifications ([more info](https://learn.microsoft.com/en-us/partner-center/account-settings/diversity-business-us))

## **Epic 1: User Authentication & Account**

Registration, login, profile management, password reset, logout, and role-based access for consumers, space providers, and administrators.

### **US-01 — Register (User) | 🔴 MUST HAVE**

* **Estimate:** 4h | **Sprint:** S2  
* **User Story:** As a visitor, I want to create a personal account so that I can book workspaces and manage my reservations.

#### **Acceptance Criteria**

* **Successful registration**  
  * **Given**: A visitor is on register with a unique, valid email.  
  * **When:** They complete all fields correctly and submit.  
  * **Then:** An account is created, a secure JWT is issued, a confirmation message is displayed, and the user is redirected to the consumer landing page.  
* **Duplicate email rejected**  
  * **Given:** An email address already exists within the platform environment.  
  * **When:** A visitor submits a registration using that exact email address.  
  * **Then:** An error message stating 'An account with this email already exists' is displayed, and no new record is created.  
* **Weak password blocked**  
  * **Given:** A visitor enters a weak value (e.g., 'pass') into the password input field.  
  * **When:** They attempt to submit the registration form.  
  * **Then:** An inline validation error describing the requirements appears, and form submission is blocked.

#### **Testing Scenarios**

* The registration form collects full name, email, password, and password confirmation. (Note: The initial role selector dropdown is completely removed).  
* Password must be 8+ characters with at least 1 number and 1 special character; mismatches show an inline error before submission.  
* All required fields must be validated client-side; empty fields block submission.

## **User Journeys (End-to-End)**

### **A) Space User Journey (Customer)**

1. **Entry Point:** Opens landing page. System defaults straight into consumer search view; no forced role configuration wall blocks entry.  
2. **Search Inputs:** Enters location targets inside the address autocomplete input field (or grants native geolocation permission triggers) and flags date parameters.  
3. **View Selection:** Sets visual presentation preferences via the toggle controls (Preserves Grid layout as native default on desktop web viewports; invokes map plotting elements as standard on mobile configurations).  
4. **Browsing Matrix:** In grid layout, scans the local workspace cards (constrained to exactly 6 records to maintain layout hygiene) and interacts with "Expand / More Venues" to reveal wider catalogue options.  
5. **Granular Filtering:** Applies operational modifiers (e.g., *No Loud Music*, *Calls Allowed*, *4+ Stars*, *Accessibility Friendly*, *Owned by...*).  
6. **Card Review:** Evaluates layout parameters displayed directly on exposed space cards (Name, aggregate stars, brief content overview, valid operational times, transparent pricing metrics) and flags **Book a Space** on a match.  
7. **In-Context Identification (If Guest):** If executing operations without an established session profile, the screen remains anchored while an inline modal displays registration/login fields. Completing details maps session cookies without triggering page redirects.  
8. **Deep Profile Review:** Inspects structural sections of target venue profiles: **Amenities** (Verified WiFi, physical outlet counts), **About this space content block**, **Complimentary Drinks matrix** (Water, tea, specialised coffee items), **Terms & Conditions guidelines**, and historical customer text logs.  
9. **Slot Selection:** Interacts with booking elements to lock timeframe windows and duration metrics.  
10. **Financial Review:** Inspects systemic calculations inside the panel structure (Hourly cost definitions, runtime totals, transparent cancellation cutoff clauses).  
11. **Checkout & Finalisation:** Confirms parameters via "Continue to Checkout", completes payment processing seamlessly using integrated automated options (Google Pay/card handling via secure Stripe infrastructure).  
12. **Receipt Allocation:** Redirects to order summaries displaying designated platform parameters (Venue name, timeframe flags, unique order index numbers).  
13. **Post-Booking Routing:** Accesses user dashboards to view localised transit options (Nearest Metro title markers plus calculated point-to-point walking minutes).  
14. **On-Site Check-In:** Upon arrival at the physical establishment, the customer accesses their dashboard profile view to present the structural **Booking ID text payload** directly to the host provider to verify access clearance.  
15. **Cancellation Controls:** Adjusts execution status codes through user dashboards within legal timeframes if scheduling adjustments occur; the system automatically deallocates timelines back to open search records.

### **B) Space Provider Journey (Venue Manager/Owner)**

1. **Registration Access:** Navigates to the platform profile layout and selects the "Register as a Space Provider" portal link positioned in the top-right toolbar.  
2. **Account Initialisation:** Formulates credential blocks. System automatically applies underlying user role codes identifying the account as a provider entity.  
3. **Awaiting Administrative Vetting:** Enters a placeholder pending page explaining that listing capabilities will unlock once administrative validation queues authorise the business profile information.  
4. **Dashboard Entry:** Upon approval, locks access to the main operational control hub showing tracking metrics (Total orders, current monthly income numbers, registered site volumes, aggregate visitor scoring histories).  
5. **Schedule Audits:** Evaluates the scrolling feed detailing scheduled upcoming client stays (Guest records, execution status, reservation blocks, pricing values).  
6. **Listing Initiation:** Clicks the prominent "Offer New Space" action button to trigger the creation wizard.  
7. **Form Completion:** Walks through the step-by-step creation wizard:  
   * Classifies space classification taxonomy (Hotel lobby, specialised cafe environments, restaurant floor zones, corporate workspaces).  
   * Pins location geographic tracking definitions.  
   * Establishes standard open operational windows alongside explicit **seat capacities and slot limits**.  
   * Toggles structural facility tags (Power capacities, infrastructure access points).  
   * Applies a conditional flag authorising or locking client scheduling extensions.  
8. **Policy Affirmation:** Interacts with legal confirmation check toggles validating understanding of system-wide operation parameters.  
9. **Publishing:** Submits details to make spaces immediately discoverable or targets "Cancel" to erase progress steps.  
10. **Live Adjustments & Check-In Handling:** Manages space details dynamically; modifies availability configurations, updates amenity flags, and manually checks in incoming workspace guests by verifying their unique **Booking ID numbers** upon arrival.

### **C) System Admin Journey**

1. **Console Authentication:** Accesses protected core routes using dedicated administrative login steps.  
2. **Platform Health Monitoring:** Scans layout metrics across platform data tables:  
   * *Financial metrics:* Global processed totals, processing rates, single ticket transaction volumes.  
   * *Space infrastructure metrics:* Total environments, volume active, counts locked in validation queues, elements under suspensions.  
   * *User engagement metrics:* Active customer indices, acquisition rates, churn analytics.  
3. **Provider Application Audits:** Opens the application review desk to evaluate business registration profiles awaiting verification. Authorises validated applications to transition their spaces to discoverable, searchable listings.  
4. **Issue Resolution:** Opens the high-severity alert queue processing unresolved customer or host complaints.  
5. **Case Evaluation:** Opens target incident modules detailing connected user logs, contextual reports, space logs, and supporting statements.  
6. **Disciplinary Execution:** Selects required automated operational protocols from workflow menus (Erase item records, dispatch systematic warning parameters, apply profile freezing steps, execute structural block protocols).  
7. **Traceability Log:** System applies actions, coordinates automatic email alerts out to affected users, and records immutable system edits directly to tracking logs for downstream auditing.
